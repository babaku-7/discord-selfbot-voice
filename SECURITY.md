# Security Policy

## Supported branch

Security fixes are currently handled on the `main` branch.

## Reporting a vulnerability

Do not open a public issue for a vulnerability. Use GitHub's private
vulnerability reporting option on the repository's **Security** tab when it is
available. If that option is unavailable, contact the maintainer through the
[GitHub profile](https://github.com/babaku-7) and ask for a private reporting
channel.

Include:

- A short description and impact.
- Reproduction steps or a minimal proof of concept.
- Affected files, versions, or commit IDs.
- Safe remediation suggestions, if known.

Never send Discord tokens, cookies, session data, passwords, private keys, or
other live credentials. Redact them from logs and screenshots. If a secret was
exposed, revoke or rotate it immediately before reporting the incident.

The maintainer will review reports as soon as practical. Do not publish
vulnerability details until a fix or disclosure plan is agreed.

## Scope note

Self-bots and user-account automation violate Discord's Terms of Service.
That policy risk is documented and is not itself a security vulnerability.
Report technical flaws privately without sharing live account credentials.
